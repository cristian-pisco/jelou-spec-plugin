# Auth Fixtures — Security Contract

> Per Premise 17 of the design doc, this reference defines how E2E tests authenticate, where credentials may live, and what the plugin will and won't do with them. The contract is non-negotiable: leaked staging-admin tokens are a real incident risk, not a hypothetical.

## Default: programmatic API login

The default auth fixture issues a fresh login on every test run. No persisted credentials, no `storageState.json` checked in anywhere.

```ts
// tests/e2e/fixtures/auth.ts (consumer service)
import { APIRequestContext, Page } from '@playwright/test';

export async function signInAs(
  page: Page,
  request: APIRequestContext,
  role: 'user' | 'admin' | string,
): Promise<void> {
  // 1. Issue a short-lived token via the consumer's test login endpoint
  const response = await request.post('/api/test/login', {
    data: { role, ttl_s: 3600 },  // ≤1 hour TTL — required by Premise 17
  });
  if (!response.ok()) {
    throw new Error(`signInAs failed: ${response.status()} ${await response.text()}`);
  }
  const { token } = await response.json();

  // 2. Inject into the browser context (cookie or localStorage; matches consumer's auth scheme)
  await page.context().addCookies([{
    name: 'auth_token',
    value: token,
    domain: 'localhost',
    path: '/',
    httpOnly: true,
    sameSite: 'Lax',
  }]);
}
```

The `/api/test/login` endpoint is a consumer-service responsibility, gated to test environments only (NODE_ENV=test or a feature flag). The plugin never embeds credentials.

## Fallback: `storageState`

Use `storageState` ONLY when programmatic login isn't available (legacy auth provider, SSO with no test mode). Even then, the contract is strict:

- File path: `<UI_SERVICE_WORKTREE>/tests/e2e/.auth/<role>.json` — under `.auth/` and gitignored.
- Token TTL: ≤1 hour.
- File regenerated by a `globalSetup` script on every run; never committed.

```ts
// playwright.config.ts (consumer service)
export default defineConfig({
  globalSetup: './tests/e2e/global-setup.ts',
  use: {
    storageState: './tests/e2e/.auth/user.json',
  },
});
```

```ts
// tests/e2e/global-setup.ts
import { chromium } from '@playwright/test';
async function globalSetup() {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  await page.goto(process.env.LOGIN_URL!);
  await page.getByLabel('Email').fill(process.env.TEST_EMAIL!);
  await page.getByLabel('Password').fill(process.env.TEST_PASSWORD!);
  await page.getByRole('button', { name: 'Sign in' }).click();
  await page.context().storageState({ path: './tests/e2e/.auth/user.json' });
  await browser.close();
}
export default globalSetup;
```

`TEST_EMAIL` / `TEST_PASSWORD` come from the local environment, never from a committed file.

## Mandatory `.gitignore` entries

Both the plugin and the consumer's repo MUST gitignore:

```
**/.auth/
**/storageState*.json
.spec-workspace/**/.auth/
.spec-workspace/**/storageState*.json
```

The plugin ships with these in its own `.gitignore`. Consumers add them to their service repo's `.gitignore` during M1's first integration.

## Pre-commit guard

The plugin ships a pre-commit hook (M2 deliverable) that rejects any commit containing files matching `**/.auth/**` or `**/storageState*.json`. The hook runs locally; CI also runs the same check on PRs.

```bash
# .git/hooks/pre-commit (snippet — installed by M2 setup)
if git diff --cached --name-only | grep -qE '(\.auth/|storageState.*\.json)'; then
  echo "ERROR: Auth fixture files cannot be committed. See jelou-ui-qa/references/auth-fixtures.md"
  exit 1
fi
```

## Token TTL: ≤1 hour

Any token used by tests has a maximum TTL of 3600 seconds. The default for `signInAs` is 3600. Longer TTLs are rejected — the writer agent will refuse to emit a fixture call with `ttl_s > 3600`.

If the consumer's auth provider doesn't support short TTLs natively, the consumer's `/api/test/login` endpoint mints its own short-lived bearer tokens that stand in for the upstream credential during tests.

## What the plugin does NOT do

- Bundle any credential, including test ones.
- Read `~/.netrc`, `~/.aws/credentials`, environment-variable secrets, or any other credential store.
- Persist a token across runs without explicit consumer opt-in via `storageState`.
- Push a branch containing files under `.auth/` (the pre-commit guard catches this; CI catches it again).

## Failure modes

- **`signInAs` returns a 401:** test fails RED with the auth error visible. The fix-loop treats this as a backend contract issue (`STATUS: BLOCKED, reason: backend_contract`) and does NOT mutate UI source.
- **Token TTL exceeded mid-suite:** the test that's running gets a 401 from a protected endpoint. The fix-loop's mid-suite crash detection (Premise 15) won't fire (the service is healthy), but the failure pattern is identifiable. M3 fix-loop heuristic: if 3+ tests in a row fail with auth-related errors, escalate `BLOCKED, reason: token_expired` and surface "regenerate fixtures and re-run."
- **`.auth/` accidentally untracked but staged:** pre-commit guard rejects.

## Consumer onboarding checklist

When a consumer service is first wired into jelou-ui-qa, the implementer (during GREEN) confirms:

- [ ] `/api/test/login` endpoint exists, gated to test env, accepts `{ role, ttl_s }`, returns `{ token }`.
- [ ] `.gitignore` includes `**/.auth/` and `**/storageState*.json`.
- [ ] `tests/e2e/fixtures/auth.ts` exports `signInAs(page, request, role)`.
- [ ] If using `storageState`, `globalSetup` regenerates the file on every run.
- [ ] Pre-commit guard installed (M2 will provide the install script).
