# Codex Runtime Contract

> Shared runtime contract for all `/jlu-*` prompts when executed under **Codex CLI**.
> Workflows in `jelou/workflows/*.md` are runtime-neutral and use the generic verbs
> `question` and `task`. This file maps those verbs to Codex behavior and records the
> Codex-specific constraints the orchestrator must respect.

## Invocation model

Use slash prompts when possible: `/jlu-load-context`, `/jlu-new-task`, and the
other generated entries in `prompts/jlu-*.md`.

If the user enters a bare `jlu-*` command token in Codex, treat it as a prompt
invocation, not as a shell command. Resolve `.codex/prompts/<command>.md` first,
then `$CODEX_HOME/prompts/<command>.md` (`$CODEX_HOME` defaults to `~/.codex`),
read the prompt, and execute it with the remaining text as arguments. If neither
prompt exists, report that the Codex prompt is not installed and ask the user to
run `./setup --host codex` from `jelou-spec-plugin` or
`bin/install-codex.sh <project>` for a project-local install. Never search
`PATH`, package scripts, or repo helpers for `jlu-*`.

## Tool / verb mapping

| Workflow says | Codex behavior | Notes |
|---------------|----------------|-------|
| `question` | Ask the user in plain text and **wait** | Codex has no structured question tool (no `AskUserQuestion`/OpenCode `question` equivalent). Present prescribed options as a numbered list. |
| `task` | Dispatch a Codex subagent, or run inline | Use a `worker`/`explorer` built-in or a named `jlu-*` agent from `.codex/agents/`. If dispatch is unavailable, do the step inline. |

## The `question` gap — read this

Codex cannot render a multi-choice prompt widget. When a workflow prescribes a
question or a confirmation:

- **Never assume the answer.** Ask in plain text and stop your turn so the user can reply.
- **Never skip a prescribed question.** The interview-driven workflows (`new-task`,
  `refine-task`, `extend-phase`, `council`) depend on real user input. Fabricating
  answers produces wrong specs.
- Present options as `1) … 2) … 3) …` and tell the user to reply with a number or free text.

## Subagent dispatch constraints

Codex differs from Claude Code / OpenCode in two ways that the orchestrator must honor:

1. **Explicit-only delegation.** Codex spawns a subagent only when explicitly asked.
   The orchestrator must phrase dispatch steps as explicit agent spawns.
2. **`agents.max_depth = 1` (default).** The orchestrator (running inline) dispatches
   workers; **a dispatched worker must not dispatch further agents.** The plugin's model
   is already flat (orchestrator → worker), so this fits — but never nest. Parallel
   fan-out across N services uses `agents.max_threads` (default 6), not depth.

When dispatching, give each worker the same focused, single-service scope and the
subagent summary contract (`jelou/references/subagent-contract.md`) as under any runtime.

## Where Codex artifacts live

| Concern | Location |
|---------|----------|
| Prompts (entry points) | `.codex/prompts/jlu-<skill>.md` (generated by `bin/sync-codex.mjs`) |
| Subagents | `.codex/agents/<agent>.toml` (generated by `bin/sync-codex.mjs`) |
| MCP + subagent limits | `.codex/config.toml` |
| PreToolUse guards | `.codex/hooks.json` (reuses `bin/guard-*.mjs`) |
| Shared workflows | `jelou/workflows/<skill>.md` (resolved global-first from `$CODEX_HOME/jelou/`) |

The prompts and agents are **generated mirrors** — edit `skills/<skill>/SKILL.md` and
`agents/<agent>.md`, then run `node bin/sync-codex.mjs`. CI fails on drift
(`node bin/sync-codex.mjs --check`).

## Usage rules

- Resolve the workflow global-first (`$CODEX_HOME/jelou/workflows/<skill>.md`), then
  project-local (`jelou/workflows/<skill>.md`). Read exactly one.
- Always reference commands with the `jlu-` prefix (never `jlu:`).
- Bare `jlu-*` input is a prompt invocation fallback. It is not a `PATH` lookup.
- Phase 1 portability: skip ClickUp/Slack execution steps if encountered; report them as deferred.

## Hooks caveat

Codex's PreToolUse hooks reliably intercept `Bash` (and, on recent versions,
`apply_patch`/MCP) — but not every shell path (`unified_exec`) or `WebSearch`. The
guards (`guard-test-commands`, `guard-env-reads`) are a guardrail, not a hard boundary;
the prompt-level rules in `jelou/references/subagent-base.md` remain the primary defense.
