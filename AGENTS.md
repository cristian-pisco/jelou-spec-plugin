# Jelou Spec Plugin (OpenCode + Codex)

This repository provides a spec-driven orchestration workflow. Both **OpenCode** and
**Codex CLI** read this file and use the hyphen-prefixed `jlu-*` command namespace.
For Claude Code, see [INVOCATION.md](./INVOCATION.md).

## Command Namespace

In OpenCode and Codex:
- Use only `jlu-*` command names (e.g., `/jlu-new-task`).
- Never invent `jlu:*` names — that prefix belongs to Claude Code only.

OpenCode command normalization:
- Treat bare `jlu-*` input as the equivalent slash command (`jlu-load-context` => `/jlu-load-context`).
- When a `jlu-*` command exists, prefer command execution over similarly named skills.
- Never route `jlu-*` invocations to non-`jlu-*` skills.

Codex command normalization:
- Prefer the explicit skill form (`$jlu-load-context`), or let Codex trigger the skill implicitly by its description.
- If the user enters a bare `jlu-*` command token (`jlu-load-context`, `jlu-load-context <args>`, "run jlu-load-context", or "use the jlu-load-context skill"), treat it as the matching Codex skill, not as a shell executable or a canonical `skills/*/SKILL.md` entry point.
- Resolve the skill from `.agents/skills/jlu-<command>/SKILL.md` (project, or `~/.agents/skills/` global), read it, and execute it with the remaining text as arguments.
- Match command names exactly. Never fuzzy-correct, complete, or infer misspelled `jlu-*` tokens.
- If no matching skill exists, stop with: "Codex skill not installed: `<command>`. Run `./setup --host codex` from jelou-spec-plugin or `bin/install-codex.sh <project>` for a project-local install." Never search `PATH`, package scripts, repo helpers, or the canonical `skills/*/SKILL.md` for `jlu-*`.

## OpenCode Runtime Contract

- Use `question` for all user prompts and confirmations.
- Use `task` for subagent dispatches.
- Shared workflows live in `jelou/workflows/*.md`.
- OpenCode-only workflow overrides live in `jelou/workflows-opencode/*.md`.
- OpenCode commands live in `.opencode/commands/*.md`.
- OpenCode subagents live in `.opencode/agents/*.md`.

## Codex Runtime Contract

Codex has no structured question tool and limits subagent nesting. See
[jelou/references/codex-runtime.md](./jelou/references/codex-runtime.md) for the full contract.

- `question` / `AskUserQuestion` → ask the user in plain text (numbered options) and **wait** — never assume, answer for the user, or skip because a structured question tool is unavailable.
- `task` → dispatch a Codex subagent (`.codex/agents/*.toml`) or run inline; never let a worker re-dispatch (`agents.max_depth = 1`).
- Codex skills live in `.agents/skills/jlu-*/SKILL.md` (mirror `.codex/skills/`); subagents in `.codex/agents/*.toml`. Both are generated by `bin/sync-codex.mjs`.
- Shared workflows are the same `jelou/workflows/*.md`, resolved global-first from `$CODEX_HOME/jelou/`.

## Code style — no line-by-line comments

When writing or editing code anywhere (this repo, generated PRs, agent output), write
**zero comments**. Do NOT add line-by-line comments that narrate what the code already
says (`// increment i`, `// return the user`, `// arrange / act / assert`), do NOT add
doc-comments or JSDoc on any declaration (class, interface, type, constant, variable,
function), and do NOT add *why* notes. Write self-documenting code: clear names, or an
extracted well-named helper, over comments. Automated PR reviewers (CodeRabbit and the
like) flag every comment in a generated diff, so a diff that adds any comment is a
defect, not documentation.

Subagents inherit this rule from `jelou/references/subagent-base.md` (the canonical
source); this section is the runtime-contract restatement so Codex and OpenCode carry it
exactly as Claude Code does via `CLAUDE.md`.

## Phase 1 Scope

- Core workflows are in scope: map-codebase, new-task, refine-task, execute-task, ship, resolve-pr, load-context. `/jlu-ship` validates that each service installs deps cleanly and builds before opening PRs — in-container for docker-compose services.
- External integrations are deferred to Phase 2:
  - `jlu-daily-slack`

If a Phase 1 run touches ClickUp/Slack integration steps, skip those steps and report that they are deferred to Phase 2.
